# WebClient.wasm: research notes and boundaries

The neighboring `WebClient.wasm` was inspected in place without running its entry point or modifying it. Selected real function bodies and static data were extracted into isolated test modules; their behavior was compared with these JavaScript ports under the limited conditions stated below.

## Binary context

- WebAssembly version 1; 101,275,588 bytes; 166,647 defined functions, 270 imported functions plus one imported shared memory, and 48 exports.
- The imported shared memory declares 4,096 to 65,536 64-KiB pages. The loaders reference WebAssembly, graphics, shared memory and fetching. The metadata index lists 30,566 assets; no actual baseplate/place asset was identified in the targeted search.
- The page is not an automatic translation of the full WASM. Scene size and placement are demo values, not extracted level data.

## Implemented fragments

- `asset-fs.js`: narrow single-threaded ports of asset register (278), inline-file add (279), base-URL set (289), and preload (291). Twenty-seven differential checks matched isolated original instructions with mocked host helpers. Locks and full file-reading behavior are not reconstructed.
- `spawn-location.js`: descriptors and getters identify Enabled, Duration, TeamColor, Neutral and AllowTeamChangeOnTouch. Constructor instructions initialize them to true, 10, 194, true and false, respectively. Selected setters matched extracted instructions in 146 checks with pre-seeded memory, mocked indirect/notification calls, and the optional instrumentation flag off. The constructor itself and spawning/team gameplay were not run in that test.
- `basepart-memory.js`: getters 137215, 137265 and 137289 expose the collision bit, size vector, and anchored bit from a preconstructed primitive. They matched 533 checks. The detached branch of size function 114423 was checked in 2,007 cases with geometry and engine hooks mocked; input storage is limited to 0.001–2048 per component while the geometry size has a 0.05 minimum. A separate linked test checked 3,004 updates using the actual Block size-copy and half-diagonal instructions; two engine calls remained mocked in that test. Attached-world updates are not implemented.
- `block-geometry.js`: the RBX::Block vtable and data in passive segment 1378 identify size copy (114617), half-diagonal (144450), rotated half-extents (144407), vertices (144437/144440), face corners (144442), and face planes (144424/144444). Tests covered 5,003 geometry cases, 3,004 vertex sets, 1,003 face sets, 1,503 plane sets and 7,009 Block volume/center cases against extracted WASM. The volume/center test uses kind 2 with no custom shape. This is geometry data, not a renderer or collision solver.
- `material-properties.js`: function 114158 chooses a custom property, world override, or default record and reads its float at offset 4. Index mapping 16094 was checked for every unsigned 16-bit input; 46 records and 6,000 selection cases were compared to linked extracted instructions with zero-initialized static storage and mocked single-thread initialization guards. The demo seeds material code 256 and stores this field, but does not use it to simulate physics.
- `primitive-chain.js`: function 115128 propagates marker flags through parent links and sets a root state. The port matched 4,001 acyclic-memory scenarios.
- `detached-block-update.js`: the normal path through 114374, including 115111, was checked in 3,500 cases for an unconnected kind-2 Block without a custom shape or observer. A linked test compared the complete detached size path (114423, Block copy/measure, null-child 114418 and restricted 114374) in 2,500 scenarios. Initialization guards, locks and allocation were mocked; exceptional and attached-world branches remain unimplemented.

- `main-event-queue.js`, `keyboard-code.js`, and `keyboard-input.js`: functions 550, 552, 566, 165748, 165750 and the 485 queue-control loop were compared in 7,500 producer and 3,000 drain scenarios. The 569 hash switch and 795 key table matched 182,095 checks, with the latter's engine consumer mocked. A linked 430/569/566 keyboard callback matched 72,040 comparisons across 12,000 scenarios with logging mocked. Tests used valid ring indices and single-threaded memory; the page uses a private 20-MiB memory image, not the original shared-memory runtime.
- `input-event-vector.js` and `input-dispatch.js`: normal 3213 repeat filtering and 3038's 12-byte vector append were compared in 5,000 dispatcher and 8,000 vector scenarios. A linked 430/569/566/795/3254/3213/3038 test, with the extracted 485 queue/tag-0 control, passed 11,002 comparisons in 500 batches. The context has no auxiliary listener or alternate event path; resolver, locking, logging and allocation are mocked. The 3107 modifier-mask switch was compared in 30,000 cases and is used on the emitted records. The rest of the gameplay consumer and focus handling are not reconstructed.

- `block-face-query.js`: for positive bounded Block dimensions and bounded finite local points, 144431 checks whether a point's projection lies inside a face; 144433 finds the nearest qualifying face. The JS simplification matched 140,049 checks across 20,007 cases against original instructions linked to the original plane helper and static topology. The demo applies the top-face predicate to its authored plate, but its height cutoff and contact response are independently written. This is not a raycast, contact generator or collision solver.

- `input-object-update-tail.js`: a pre-resolved object-update tail from 99505 was linked to actual functions 86260 and 86280 in a synthetic WASM test. It matched 60,000 comparisons over 20,000 cases for the dispatch gate, object bytes and ordered mock callbacks. Property setters 54510/54475, notifications and the signal are mocked; lookup, ownership, position, actual dispatch 92288 and the rest of 99505 are not reconstructed. The page uses its own synthetic object per key and chooses a released initial state; neither the lookup nor that initial state is established as original behavior.

- `world-step-accumulator.js`: a restricted non-throttled normal branch of function 89079 computes accumulated f32 steps, the floored count, a cap of `max(12, signed setting at 9031000)`, retained backlog (at most f32 1.99999), dropped backlog and the returned count. A JS port and an isolated original-instruction slice matched 250,000 comparisons across 50,000 cases. Test conditions: nonnegative finite values; no forced-step, alternate-ownership or throttle paths; the flag/lookup and logging callbacks were not exercised. The page chooses a 240 Hz demo rate and zero cap setting; neither is established here as a target-build default. These step counts drive independently written demo updates, not recovered physics. Other parts of 89079 and the solver are unimplemented.

## Demo glue and remaining work

The page triangulates the recovered quad perimeters itself and uses a separate WebGL shader, camera, character, keyboard-to-movement adapter, touch input, ground check and jump/gravity. The scene is stored in the partial asset port but read back through its JavaScript snapshot. These are not evidence of equivalence to WebClient. Scripting, networking, replication, game services, actual spawning, collisions and production physics are missing. More bytecode tracing and comparisons are required before calling this a recreation of the engine.
